LLM Eval Progress Report ↗

We train a small transformer to classify how many moves a 2×2×2 Rubik's cube is from solved (0–11), then apply mechanistic interpretability tools to understand what it learns and how. The cube is an ideal controlled setting: small enough that every representation can be probed exhaustively, but structurally complex enough to require non-trivial computation. Use the visualizer below to scramble and step through BFS-optimal solutions.

A parallel line of work (LLM Eval ↗) benchmarks seven pre-trained models across eight text representations of cube state — from face grids to cycle notation — testing whether in-context reasoning alone can solve scrambles. Spoiler: no state representation works; only move_sequence (trivial inversion) separates models.

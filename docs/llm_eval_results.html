Phase 17 — LLM Evaluation: Which Representation Best Enables Solving?

Question: Which text representation of the cube state gives a general-purpose LLM the best chance of solving it?

Method: Eight representations (face_grid, compact_string, corner_cubies, piece_identity, move_sequence, natural_language, perm_orient, cycle_notation) are tested at distances 3, 5, 7, 9, and 11 with a one-shot prompt. Solve rate and solution length are measured.

Baseline: move_sequence gives the model the scramble moves directly — any model that can reverse a sequence achieves a near-100% ceiling. The other representations require genuine spatial reasoning.

To add a model: set its API key env var and run uv run python test_representations.py --models MODEL_NAME. Results accumulate across runs.

Prompt Format & Representation Examples

Each trial uses a two-part prompt: a system message instructing the model to output only a move sequence, followed by a one-shot user message containing a solved-state example and then the actual scrambled state. Below is the exact system message and the eight representation formats shown for a single 3-move scramble (U' L2 B).

System message (identical for all representations)

You are an expert at solving 2x2x2 Rubik's cubes.

Move notation:
- U/D/F/B/L/R = top/bottom/front/back/left/right face
- No suffix = 90° clockwise (when looking at that face head-on)
- ' suffix = 90° counterclockwise
- 2 suffix = 180°

The cube is solved when every face shows a single color.
Standard solved orientation: White on top (U), Green in front (F), Red on right (R),
Orange on left (L), Blue on back (B), Yellow on bottom (D).

Do NOT write code, pseudocode, or algorithms of any kind.
Do NOT explain your reasoning or describe your approach.
Respond with ONLY the solution move sequence, moves separated by spaces.
No explanation. No extra text. Example: U R' F2 D B2 L

The user message contains one solved-state example (distance 0) followed by the scrambled state. For instance, the compact_string user message would be:

User message structure (compact_string example)

Example:
Standard orientation: White on top (U), Green in front (F)
Format: 6 faces × 4 stickers, reading order (TL TR BL BR) as viewed from outside.
Face order: U D F B L R

U:WWWW D:YYYY F:GGGG B:BBBB L:OOOO R:RRRR

---
Now solve this cube:
Standard orientation: White on top (U), Green in front (F)
Format: 6 faces × 4 stickers, reading order (TL TR BL BR) as viewed from outside.
Face order: U D F B L R

U:GRYW D:WYOB F:BORG B:BROG L:WOYB R:GYRW

The eight representations for the scramble U' L2 B (distance = 3, solution = B' L2 U):

face_grid

Standard orientation: White on top (U), Green in front (F)
Each face shown as viewed from outside the cube.

        U (top):
        G R
        Y W

L (left)    F (front)   R (right)   B (back)
W O          B O          G Y         B R
Y B         R G         R W         O G

        D (bottom):
        W Y
        O B

Spatial layout. Provides visual context but requires the model to mentally rotate and track sticker positions — no model solved any cube using this format.

compact_string

Standard orientation: White on top (U), Green in front (F)
Format: 6 faces × 4 stickers, reading order (TL TR BL BR) as viewed from outside.
Face order: U D F B L R

U:GRYW D:WYOB F:BORG B:BROG L:WOYB R:GYRW

Compact 24-character encoding. Information is complete but requires spatial reasoning to decode — zero solves across all models.

corner_cubies

Standard orientation: White on top (U), Green in front (F)
There are 8 corner cubies. Each is described by the color visible on each face at that corner position.

Solved state for reference:
  UFR:(U:W F:G R:R)  UFL:(U:W F:G L:O)  UBL:(U:W B:B L:O)  UBR:(U:W B:B R:R)
  DFR:(D:Y F:G R:R)  DFL:(D:Y F:G L:O)  DBL:(D:Y B:B L:O)  DBR:(D:Y B:B R:R)

Current state:
  UFR:(U:W F:O R:G)
  UFL:(U:Y F:B L:O)
  UBL:(U:G B:R L:W)
  UBR:(U:R B:B R:Y)
  DFR:(D:Y F:G R:R)
  DFL:(D:W F:R L:B)
  DBL:(D:O B:G L:Y)
  DBR:(D:B B:O R:W)

Per-corner description. Includes solved reference, making the goal explicit. Near-zero solve rate (1/50 for Claude Sonnet 4.6 at d=3) — almost no models can convert this into moves.

piece_identity

Standard orientation: White on top (U), Green in front (F)
8 corner pieces, each named [W/Y]-[F/B-color]-[L/R-color] as in the solved state.
Goal: every piece at its home position with its W or Y sticker facing U or D.

Solved reference:
  W-G-R@UFR  W-G-O@UFL  W-B-O@UBL  W-B-R@UBR
  Y-G-R@DFR  Y-G-O@DFL  Y-B-O@DBL  Y-B-R@DBR

Current state (piece → current position, which face its W/Y sticker faces):
  W-G-R: at UBL, W faces L — needs to move to UFR + twist
  W-G-O: at UFR, W faces U — needs to move home (UFL)
  W-B-O: at DBR, W faces R — needs to move to UBL + twist
  W-B-R: at DFL, W faces D — needs to move home (UBR)
  Y-G-R: solved
  Y-G-O: at DBL, Y faces L — needs to move to DFL + twist
  Y-B-O: at UFL, Y faces U — needs to move home (DBL)
  Y-B-R: at UBR, Y faces R — needs to move to DBR + twist

Semantic piece-tracking with explicit goal annotations. Despite the helpful framing, no model could convert the placement information into a valid move sequence.

move_sequence — only format that works

Standard orientation: White on top (U), Green in front (F)
Starting from the solved state, the following scramble was applied:

  U' L2 B

Trivial inversion: the model just needs to reverse the sequence (B' L2 U). This is not genuine spatial reasoning — it is pure sequence manipulation. Models that can reliably reverse sequences score high; those that cannot (e.g., llama-3.3-70b-versatile) score near zero even here.

natural_language

Standard orientation: White on top (U), Green in front (F)
The cube has 8 corner pieces, each identified by its 3 colors.
Goal: every piece at its home position with white or yellow facing up or down.

The white-green-orange corner is at top-front-right (home: top-front-left), white correctly faces top — needs to move.
The yellow-blue-orange corner is at top-front-left (home: bottom-back-left), yellow correctly faces top — needs to move.
The white-green-red corner is at top-back-left (home: top-front-right), white faces left — needs to move and twist.
The yellow-blue-red corner is at top-back-right (home: bottom-back-right), yellow faces right — needs to move and twist.
The yellow-green-red corner is solved at bottom-front-right.
The white-blue-red corner is at bottom-front-left (home: top-back-right), white correctly faces bottom — needs to move.
The yellow-green-orange corner is at bottom-back-left (home: bottom-front-left), yellow faces left — needs to move and twist.
The white-blue-orange corner is at bottom-back-right (home: top-back-left), white faces right — needs to move and twist.

Verbose natural-language corner description with explicit move/twist hints. Despite the human-readable framing, models achieved 0% solve rate — the gap between understanding the description and planning moves is too large.

perm_orient

Standard orientation: White on top (U), Green in front (F)
Corner slots indexed 0–7: 0=UFR 1=UFL 2=UBL 3=UBR 4=DFR 5=DFL 6=DBL 7=DBR
Solved state: perm=[0,1,2,3,4,5,6,7]  orient=[0,0,0,0,0,0,0,0]

perm[i]   = home-position index of the piece currently at slot i
orient[i] = 0 if the W/Y sticker faces U or D (correct)
            1 if the W/Y sticker faces F or B
            2 if the W/Y sticker faces L or R

perm  : [1, 6, 0, 7, 4, 3, 5, 2]
orient: [0, 0, 2, 2, 0, 0, 2, 2]

Compact algebraic encoding: permutation vector plus orientation vector. Completely lossless and unambiguous, but requires the model to reason in group-theoretic terms. Zero solves across all models.

cycle_notation

Standard orientation: White on top (U), Green in front (F)
(A B C) means: piece from home A is at slot B, piece from home B is at slot C, piece from home C is at slot A.
Twist key: 1 = W/Y sticker faces F/B, 2 = W/Y sticker faces L/R (0 = correct, omitted).

Corner permutation: (UFR UBL DBR UBR DFL DBL UFL)
Twisted corners:     UBL:2  UBR:2  DBL:2  DBR:2

Group-theoretic cycle notation for corner permutation plus per-corner twist values. The most compact algebraic form — zero solves, as models cannot map cycle notation to concrete moves.
